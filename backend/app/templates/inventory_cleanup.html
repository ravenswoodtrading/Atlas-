Finds Amazon SKUs that are genuinely sold out -- zero stock (fulfillable, inbound, and reserved all zero) and confirmed evidence it actually sold at some point -- and lets you delete the listing straight from here.

"Sold evidence" is one of two signals, shown per row. Most SKUs carry a date in their own SKU name -- if that date is old enough, the listing itself is old enough to trust as sold-through evidence, even with zero units showing in the last 30 days. SKUs that don't carry that date pattern fall back to Amazon's own fulfilled-shipments report instead, which currently only sees the last 30 days.

A SKU with zero stock but no confirmed evidence either way is never shown here at all -- that's a listing that hasn't been stocked yet, not one that sold through, and this page deliberately leaves those alone.

"Days out of stock" counts from whenever Atlas FIRST detected this specific stockout -- it resets to 0 for a SKU that restocks and later sells through again, and it also reads low right after Atlas starts tracking something new, even if the listing itself has clearly been dead much longer (that's what "Sold evidence" is for -- an old SKU date is real proof on its own, independent of this counter).

"Ready to review" means it's passed {{ min_days }} days since first detected -- but Delete and Dismiss both work from "Still monitoring" too, so you're never forced to wait that out if the sold evidence already convinces you. Nothing is ever deleted automatically either way -- select rows and click Delete, which removes the listing from Amazon via the Listings API (not easily reversible).

"Snooze {{ dismiss_snooze_days }}d" is never permanent -- it just stops flagging a SKU for {{ dismiss_snooze_days }} days (e.g. you know an inbound shipment is on its way but Amazon hasn't reflected it yet), then a later sweep re-checks it completely fresh. If it's still genuinely zero stock with confirmed sold evidence once the snooze expires, it comes straight back -- possibly straight into "Ready to review" if it's already been out of stock long enough, since the days-out-of-stock clock keeps running the whole time, it doesn't reset.
